
# API Client

This document lists the frontend's API usage as it exists in the repository, grouped by unique endpoint. As of the feature-based restructure, **every HTTP call in the codebase now lives in a named `api/*.api.js` function** — no component or page calls `axiosInstance`/`adminAxiosInstance` directly anymore. Where a call used to be inline inside a component, that's noted below so you know where it moved.

## Calls Moved Out Of Components, Into Feature `api/` Modules

This section previously documented direct `axiosInstance`/`adminAxiosInstance` calls made inline inside components and pages. As part of the restructure, **every one of these was extracted into a named function** in the owning feature's `api/*.api.js` file. The table below shows the new home for each; the component listed under "caller" now imports the named function instead of calling axios itself.

## Notes On Shape Consistency

- No contradictory request payload shapes were found for the repeated endpoints in the inspected files.
- `POST /auth/login` consistently uses `{ email, password }`.
- `POST /support/messages` consistently sends the form fields plus `role`.

## Scope Note

This document covers the endpoint surfaces used in `src/features/*/api/`, Redux thunks in feature `store/` slices, and every call that was previously inline in a component or page (all of which have now been extracted). Hook-level axios usage (e.g. `useTrackEarnings.js`, `useSlotLock.js`) is intentionally left in the hook — hooks are already the correct layer for API calls, so those were not moved.
